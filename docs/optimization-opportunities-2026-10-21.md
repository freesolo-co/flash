# Optimization opportunities from the October 21 E2E audit

These are proposed follow-ups, not measured speedup claims. The [companion qualification report](e2e-qualification-2026-10-21.md) records actual results and coverage limits. Fix correctness and release compatibility before comparing throughput.

| Priority | Opportunity | Evidence and next measurement |
| --- | --- | --- |
| P0 | Gate releases on the exact worker image that training selects | `main` required upstream Verl `ddf70072…`, while the selected `cu128-sm90` image installed the retired Freesolo fork `32d6200d…`. A green CPU suite did not catch this. The accompanying fix pins the compatible image. Add an image provenance check and one paid optimizer/checkpoint smoke to release promotion. |
| P0 | Validate trainer provenance before downloading model weights | The incompatible SFT worker downloaded the 9B checkpoint before failing upstream validation. Run the existing provenance check in the chosen trainer interpreter during bootstrap, before dataset staging and weight hydration; verify that failures preserve useful diagnostics and release the GPU. |
| P1 | Restore qualified per-architecture kernel images using immutable digests | The old SM90 image reported a Python/cache mismatch and fell back to JIT. The safe image pin sacrifices potentially warm per-SM caches. Bake against the selected trainer image, verify both base and cache fingerprints, record immutable digests, and measure cold time on each supported architecture before enabling them. |
| P1 | Measure cold startup separately from generation | The serving tests spend time downloading weights, compiling graphs, profiling vision, and capturing CUDA graphs. Base-runtime engine startup measured about 503 seconds (9B), 1,059 seconds (27B), and 920 seconds (35B), including the configured startup work. Customer-owned deployment also restarts after removing the artifact secret; measure both phases. Report those stages individually alongside time to first token and steady-state tokens/second. Compare cold caches with persistent weights and compiled caches; do not count download time as model inference latency. |
| P1 | Separate cold setup cost from the customer quote for tiny runs | The two-step 35B CLI run quoted $0.15; worker start/terminal timestamps imply about $1.91 in reserved Modal GPU/CPU/RAM before final CPU publication. This is a provider estimate, not an invoice. Measure cold and warm startup amortization across run lengths before changing quotes, minimum charges, or batching policy. |
| P1 | Reuse model caches within compatible placements | Independent smoke runs repeatedly fetched the same 9B weights. Use one owned cache for compatible runs and record the physical region. Compare cold and warm runs; avoid forcing cross-region storage or changing tenant isolation. |
| P1 | Tune serving capacity per workload | Profiles reserve 32K context and multiple LoRA slots even for short smoke prompts. Benchmark realistic text, image, and concurrent adapter workloads before changing context, batch-token caps, sequence count, or LoRA capacity. Measure peak memory, p95 latency, and throughput together. |
| P1 | Keep structured output and tool-call coverage in the paid canary | Mocked engines cannot establish grammar compilation, real tokenizer rendering, generated call parsing, or successful history replay. Use deterministic schemas, semantic assertions, raw SSE reconstruction, and an actual tool-result follow-up. Keep unsupported combinations as explicit rejection tests. |
| P1 | Surface effective training width before paid allocation | The small unpacked GDN SFT fixture used one rank on a two-H100 allocation, with the existing idle-card warning. Confirm that public preflight exposes the effective batch/rank calculation before launch; retain explicit-count semantics and test divisible GRPO batches separately. |
| P2 | Add a budgeted, resumable qualification driver | Record source/image/model revisions, owned resource IDs, launch times, bounded deadlines, results, and cleanup receipts before proceeding to the next stage. Charge estimates must include Sandbox CPU/RAM, image builds, storage, and serving idle time; a GPU-only estimate is incomplete. |
| P2 | Benchmark checkpoint publication independently | Compact checkpoints and final CPU upload are already implemented. The 27B CPU publication stage took about 196 seconds; the 35B MoE rank-8 adapter alone was about 945 MB. Measure GPU release time, CPU upload duration, recovery download time, and exact resumed adapter equivalence. Compare these existing paths before proposing additional compression or transfer concurrency. |

Modal estimates use the [published pricing](https://modal.com/pricing), checked October 21, 2026 Pacific time. Sandbox CPU and memory have separate rates; requested regions can add premiums. These estimates are not a billing invoice.
