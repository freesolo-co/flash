# Follow-ups from the production retest

These are proposals based on observed behavior, not measured speedup claims. See the [production retest report](production-retest-2026-10-22.md) for test outcomes.

| Priority | Proposal | Evidence and validation |
| --- | --- | --- |
| P0 | Check registry access for every production image before declaring a release deployed. | The VM token authenticated to GitHub and could pull the backend image, but Flash and agent-worker pulls returned 403. Validate the exact package/tag manifest for each service, then verify the running release identity. |
| P0 | Alert when the deployed control plane falls behind the intended release. | CI and serving deployment were green while the control plane remained on 1.3.11 instead of 1.3.23. Publish intended and observed versions together; alert on a sustained mismatch and include the deploy timer's last pull error. |
| P1 | Give the deployment timer a dedicated account/token with package-read access to all required images. | Docker previously used a different identity from the service credentials. This repair reused an existing authorized credential already on the VM. A dedicated narrow credential would make ownership, access checks, and rotation explicit. Validate all image pulls before rotating it. |
| P1 | Make end-to-end qualification resumable and enforce one cumulative budget. | This retest carries forward the prior audit's conservative spend estimate, records owned resources, reserves each training watchdog window, and delays serving until training finishes. Package that workflow so future audits cannot accidentally reset the budget or leave idle serving capacity while training. |
| P1 | Measure cold setup, training, checkpoint publication, and inference separately. | Tiny correctness runs do not establish throughput or model quality. Record stage timings and hardware/image identities before tuning cache reuse, concurrency, or checkpoint transfer. |
| P2 | Refresh documentation against live deployment metadata. | The serving contract document describes hosted 27B on H100, while the current production health endpoint reports B200 for all three hosted base models. Generate or verify hardware examples from release metadata to prevent drift. |
| P2 | Measure and expose worker-to-control-plane progress lag. | During structured OPD, the worker console had reached checkpoint publication/finalization while the public status still showed model loading. Compare heartbeat timestamps, storage publication delay, and controller polling before changing caching or polling intervals; distinguish training, GPU shutdown, CPU upload and reconciliation in status. |
| P1 | Run the audit controller on an always-on runner and retry transient read timeouts. | macOS entered repeated maintenance sleep during this audit. The local harness timed out and cancelled one owned 35B OPD run. Its replacement runs with temporary sleep prevention and bounded polling retries. Production training should be observed independently of a laptop session. |
| P1 | Profile and qualify H200 MoE/LoRA kernel cache coverage. | The two-H200 35B OPD worker logged fallback MoE/LoRA kernel configurations and only reached CUDA graph capture several minutes after launch. Compare cold and warm launch timings, exact model/GPU/image signatures, and output equivalence before adopting tuned configurations or broader cache reuse. No speedup is claimed from this observation alone. |
| P1 | Document thinking-mode sampling and visible truncation handling. | A 9B prompt looped at temperature=0 and exhausted 768 and 4096 reasoning tokens. The identical prompt completed for seeds 42 and 43 with temperature=1, top_p=0.95, presence_penalty=1.5 and max_tokens=4096. These supported settings follow the [Qwen model guidance](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices); unexposed top_k/min_p were not tested. Surface finish_reason=length rather than presenting an empty answer as successful JSON. Do not claim this eliminates every model-quality failure. |

| P0 | Qualify disconnects against replica survival as well as HTTP cleanup and billing. | The live disconnect checks produced correctly quarantined, unbilled receipts, but Modal later killed both affected GPU replicas after a 30-second cancellation watchdog. Include a concurrent sibling request and assert the same replica remains healthy beyond that watchdog. The proposed code fix connects the existing leased queue channel to hosted serving. |
| P1 | Derive audit cost reservations from deployed scaling settings and actual container lifetimes. | The initial harness assumed a five-minute tail; production retains B200 replicas for 35 minutes and allows up to four per model. Corrected accounting uses task enqueue/finish timestamps, includes replacement replicas, and reserves the full idle tail. Tune the production window only after measuring cold-start latency and real traffic gaps. |
