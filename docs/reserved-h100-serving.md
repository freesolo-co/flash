# Reserved 9B Base serving

Production `Qwen/Qwen3.5-9B-Base` uses separately reserved Lambda H100 workers: serving declares up to eight slots (`reserved.SLOT_COUNT`) and the workers secret configures any non-empty subset of them. Each slot has a dedicated CPU-only Modal proxy with a one-container ceiling. The router rotates requests across the routable configured proxies and sends adapter registration/removal to each routable worker. Other models retain their existing shared-capacity behavior.

Registration is per worker and bounded: a checkpoint is promoted once any routable worker loads it, and a worker that missed it loads it on first use. The `reserved_h100_watchdog` scheduled function probes each worker directly every two minutes with `/health` plus a one-token base-model generation, because a worker can answer health while its generations never finish. Two consecutive failures quarantine a worker; the router then skips it for requests and registrations, failing open if every worker is quarantined. Only a worker whose `/health` reports `canary_lane` (a dedicated canary admission lane) fails a probe on a canary timeout alone; on older workers the canary queues behind every admitted generation, so a timeout with healthy `/health` counts as busy and is held against the worker only after no canary has completed for twenty minutes. A worker unhealthy for ten minutes is rebooted through the Lambda API with the reservation secret, at most once per thirty minutes, keeping its instance, IP, certificate and token; it rejoins after its next passing probe. Slot states live in the Modal Dict `flash-reserved-h100-health-20261112`, together with `configured_slots`, which the watchdog publishes after each cycle from the workers secret; the router never routes to a declared slot outside it. To add workers: deploy serving with enough declared slots, qualify the new workers, write them into the secret, and clear any stale health entries for those slots.

Worker addresses, instance identities, source revisions, certificate pins and bearer tokens live in the main-environment Modal Secret `flash-reserved-h100-workers-20261112`. Never commit those values. Proxies validate worker model, revision and H100 identity before accepting calls. Proxy shutdown closes its client without terminating the reserved VM.

9B Base has no Modal GPU fallback in main or dev. Main forbids automatic Lambda allocation for this model. Development retains a scale-to-zero Lambda-only path, isolated from production's reserved workers and credentials.

The separate `flash-h100-reservation-20261112` operation owns retention for the instances named `flash-h100-reservation-20261112-1` through `-4`; workers added beyond those four are not owned by its scheduler and must be terminated explicitly when the reservation ends. Its authoritative state and `hold_until` are in the same-named Modal Dict. Explicitly transfer lifecycle responsibility before stopping that scheduler. That scheduler terminates its instances once `hold_until` passes, so while its `mode` is `serving` the watchdog renews the hold every cycle it finds less than seven days left, extending it to thirty days ahead under the scheduler's own `tick_lock` (a lock older than fifteen minutes was left by a killed tick and is replaced), and logs `reserved H100 alert: ...` whenever a hold that is not being renewed is within 24 hours of expiry. The reservation inventory is separate from ephemeral `flash-main-*` workers and their idle reaper.

Qualify every worker before it is written into the secret: pinned-runtime lock verification, GPU/model identity, buffered and streamed generation, cancellation, and an authenticated public-endpoint canary. Drain prior 9B Base requests before terminating old dynamic workers. Reverting the routing code restores the prior dynamic paths; review capacity and live instances before rollback.
