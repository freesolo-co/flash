# Reserved 9B Base serving

Production `Qwen/Qwen3.5-9B-Base` uses separately reserved Lambda H100 workers: serving declares up to fifteen slots (`reserved.SLOT_COUNT`); the workers secret configures any non-empty subset of them, and the expansion loop (below) adds qualified workers for target slots the secret does not hold. Each slot has a dedicated CPU-only Modal proxy with a one-container ceiling. The router rotates requests across the routable configured proxies and sends adapter registration/removal to each routable worker. Other models retain their existing shared-capacity behavior.

Registration is per worker and bounded: a checkpoint is promoted once any routable worker loads it, and a worker that missed it loads it on first use. The `reserved_h100_watchdog` scheduled function probes each worker directly every two minutes with `/health` plus a one-token base-model generation, because a worker can answer health while its generations never finish. Two consecutive failures quarantine a worker; the router then skips it for requests and registrations, failing open if every worker is quarantined. Only a worker whose `/health` reports `canary_lane` (a dedicated canary admission lane) fails a probe on a canary timeout alone; on older workers the canary queues behind every admitted generation, so a timeout with healthy `/health` counts as busy and is held against the worker only after no canary has completed for twenty minutes. A worker unhealthy for ten minutes is rebooted through the Lambda API with the reservation secret, at most once per thirty minutes, keeping its instance, IP, certificate and token; it rejoins after its next passing probe. Slot states live in the Modal Dict `flash-reserved-h100-health-20261112`, together with `configured_slots`, which the watchdog publishes after each cycle from the workers secret plus the published expansion workers; the router never routes to a declared slot outside it. To add workers: deploy serving with enough declared slots, qualify the new workers, write them into the secret, and clear any stale health entries for those slots.

Worker addresses, instance identities, source revisions, certificate pins and bearer tokens live in the main-environment Modal Secret `flash-reserved-h100-workers-20261112`. Never commit those values. Proxies validate worker model, revision and H100 identity before accepting calls. Proxy shutdown closes its client without terminating the reserved VM.

9B Base has no Modal GPU fallback in main or dev. Main forbids automatic Lambda allocation for this model. Development retains a scale-to-zero Lambda-only path, isolated from production's reserved workers and credentials.

The separate `flash-h100-reservation-20261112` operation owns retention for the instances named `flash-h100-reservation-20261112-1` through `-4`; workers in any other slot (5–8 today) are not owned by its scheduler; see [Slots outside the reservation](#slots-outside-the-reservation). Its authoritative state and `hold_until` are in the same-named Modal Dict. Explicitly transfer lifecycle responsibility before stopping that scheduler. That scheduler terminates its instances once `hold_until` passes, so while its `mode` is `serving` the watchdog renews the hold every cycle it finds less than seven days left, extending it to thirty days ahead under the scheduler's own `tick_lock` (a lock older than fifteen minutes was left by a killed tick and is replaced), and logs `reserved H100 alert: ...` whenever a hold that is not being renewed is within 24 hours of expiry. The reservation inventory is separate from ephemeral `flash-main-*` workers and their idle reaper.

Qualify every worker before it is written into the secret: pinned-runtime lock verification, GPU/model identity, buffered and streamed generation, cancellation, and an authenticated public-endpoint canary. Drain prior 9B Base requests before terminating old dynamic workers. Reverting the routing code restores the prior dynamic paths; review capacity and live instances before rollback.

## Slots outside the reservation

The reservation scheduler's source is in [`deploy/reserved-h100/`](../deploy/reserved-h100/README.md), which also gives its safe deploy order. Its instance inventory is its own state, and Flash cannot extend it. The watchdog renews one `hold_until`, so renewal covers only the scheduler's own instances (`-1` through `-4`). Workers in other slots are deliberately left out: absorbing them would change who may terminate them, which needs an explicit operator decision. Until an operator transfers them, they have this lifecycle:

- **Renewal.** None needed. No `hold_until` applies to them, so they never expire and keep billing until someone terminates them.
- **Expiry.** When the reservation's `hold_until` passes, the scheduler terminates only `-1` through `-4`. Other slots keep serving. The router still routes only to configured slots, so if those slots remain in the workers secret, 9B Base keeps serving on them alone.
- **Teardown** (when the reservation ends, or to shrink the fleet). Run these steps for each slot outside the reservation:
  1. Remove the slot from `flash-reserved-h100-workers-20261112`, keeping at least one slot configured. Record its `instance_id` first. Editing the secret does not change a container that is already running: the watchdog reads the workers secret from its container environment, which is fixed at container start, so a warm watchdog container keeps publishing the old slot list. Stop any `reserved_h100_watchdog` container that started before the edit (`modal container list`, then `modal container stop <id>`).
  2. Confirm routing removal before going further. Read `configured_slots` from the health Dict `flash-reserved-h100-health-20261112` until a watchdog cycle that started after step 1 has published a list without the slot. The watchdog publishes only after it finishes that cycle's probes, so this can take longer than one two-minute period. Routers cache their view for 15 seconds (`ROUTER_CACHE_SECONDS`), so wait at least that long after the confirmed publish. Only then has the router stopped routing and registering to the slot. Then wait out the full router request deadline (`ROUTER_TIMEOUT_SECONDS` in `flash/serving/app/timeouts.py`, two hours today), so that requests routed before removal can finish. Worker `/health` does not report admitted or active generations, so it cannot show that the worker has drained.
  3. Terminate it with the reservation's Lambda key: `POST https://cloud.lambda.ai/api/v1/instance-operations/terminate` with `{"instance_ids": ["<instance_id>"]}`, one id per request. Do not use Flash's `terminate_confirmed`; it refuses serving VMs by design.
  4. Poll `GET /api/v1/instances/<instance_id>` until it returns 404 or `status` is `terminated`. Then check `GET /api/v1/instances` to confirm that no unlisted reserved H100 is still running.
  5. Delete the slot's entry from the health Dict `flash-reserved-h100-health-20261112`, so that a later re-add starts clean.

## Expansion slots (9-15)

`reserved_h100_expansion` (`reserved_expansion.py`, main only, every two minutes) fills the target slots the workers secret does not hold (Dict key `target_slots`, default `[9, 10, 11, 12, 13, 14, 15]`). When Lambda has single-H100 capacity it launches one worker per cycle, named `flash-h100-reservation-20261112-<slot>`, with the dynamic-worker cloud-init at the serving deploy revision; otherwise it retries next cycle. A worker that passes the proxy identity check and a canary is published to `workers` in the Modal Dict `flash-reserved-h100-expansion-20261121`, which the watchdog and proxies read beside the secret. A vanished instance is unpublished and replaced. Launches are at-most-once: the slot record is written first, and an ambiguous launch is not resubmitted for 30 minutes. A placement Lambda rejects is skipped for 10 minutes. The loop never terminates anything. Expansion workers have no `hold_until` and bill until terminated.

**Scale back to 8:** set `target_slots` to `[]`, then follow the teardown above for each expansion slot, removing it from `workers` (instead of the secret) and deleting its `slot-<n>` record.
