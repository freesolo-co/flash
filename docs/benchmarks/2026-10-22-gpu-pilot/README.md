# Live GPU benchmark pilot — 2026-10-22

Four real Flash training jobs completed on Modal H100 80 GB GPUs, followed by GPU inference evaluation. This is a one-seed pilot with 64 training examples and 64 disjoint held-out examples from a custom MMLU-Pro “other” split. It is not an official MMLU-Pro score.

## Training results

The pinned Qwen3.5-9B base scored **57.81%** on the held-out set. The predeclared target was 65% accuracy. Each question changes the score by 1.5625 percentage points.

| Run | Steps | Complete job time | Model download | Final held-out accuracy | Region |
|---|---:|---:|---:|---:|---|
| sft-cold | 64 | 8m 11.1s | 95.9s | 57.81% | uk |
| sft-warm | 64 | 4m 29.0s | 0.0s | 57.81% | ap-south |
| grpo-cold | 8 | 11m 04.0s | 120.9s | 56.25% | ap-south |
| grpo-warm | 8 | 8m 22.0s | 0.0s | 57.81% | eu-west |

Job time starts before submission and ends after artifact publication and provider cleanup. Cold means a fresh model-cache volume; warm means a new process using that workload’s populated volume, with a fresh adapter and optimizer. The region was not fixed, so the paired difference is not a controlled estimate of caching’s causal effect.

Quality was measured after training, at both saved checkpoints and the final saved step. These observations do not establish online time or cost to a quality target; those fields remain null. The pilot does not demonstrate general quality improvement or statistical superiority.

Save-checkpoint timing does not include every asynchronous artifact upload. Full worker training-wall metrics also include initialization and checkpoint work. Missing attribution remains unknown.

The evaluation engine took **454.0s** to initialize. A retained process/GPU snapshot showed FlashInfer GDN CUDA compilation while the H100 reported 0% utilization. This inference microbenchmark uses the pinned training image, not the production serving deployment profile; the observation does not quantify a production-wide savings estimate.

## Concurrent adapters and multi-turn inference

The same inference engine tested two distinct trained adapters with eight total requests in flight. Each synthetic customer supplied 32 held-out requests per condition. Latency covers the local GPU engine request, excluding hosted HTTP, authentication, routing, and customer isolation.

| Condition | Adapter/customer | Requests | p50 | p95 |
|---|---|---:|---:|---:|
| isolated | sft-warm-step64 | 32 | 281.4ms | 292.5ms |
| isolated | grpo-warm-step8 | 32 | 297.7ms | 306.2ms |
| concurrent | sft-warm-step64 | 32 | 296.6ms | 307.4ms |
| concurrent | grpo-warm-step8 | 32 | 297.1ms | 304.1ms |

The base model completed **0/8** tool-use episodes correctly, with **104** model turns and a maximum of **13** turns per episode. Each episode required twelve ordered lookups and a final sum. This tests multi-turn inference; long-agent reinforcement-learning training and hosted multi-customer isolation remain unqualified.
